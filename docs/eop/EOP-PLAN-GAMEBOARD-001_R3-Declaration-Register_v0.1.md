## Cross-cutting findings for the ruling

1. **The 5 `any non-terminal` cases are not fixable by substituting a value.** `enforce_requires_states_precondition_with_mode` (`src/dsl_v2/executor.rs:2200-2206`) does `lifecycle.requires_states.iter().any(|s| s == &current_state)` — a literal membership check. `"any non-terminal"` can never equal a real column value; these 5 verbs are refusing (or, under fail-open, silently passing) **unconditionally**, regardless of the entity's real state, today. Closing this needs either (a) a ruling that spells out the concrete non-terminal state list per slot as a real value list, or (b) a new declaration shape (`requires_states_not_in: [...]` or similar) plus a matching code path — the latter is the more honest fix if "terminal" is meant to survive future new states being added without re-authoring every verb, but it's new declarative surface, which §0 says "code declares what a rule means" already covers via typed Rust — worth deciding which side of that boundary this belongs on.
2. **`screening.run` is a structural (wrong-slot) finding, not a vocabulary typo** — see its row above. This is arguably the most important single row in this register, since it's the one already cited in CLAUDE.md/§1 fact 3.
3. **Three separate cross-contamination instances** (`governance.publish`'s `draft`, `trading-profile.create-draft`'s `parties_assigned`, and arguably `evidence.mark-verified`'s `evidence_collected`) suggest these verbs' `requires_states` lists may have been authored by copy-pasting from a sibling verb in a different domain/workspace, then only partially corrected. Worth a lighter-weight, repo-wide grep for the same pattern beyond just these 87 verbs, as a follow-up (not done here — out of R3's stated scope).
4. **10 of the 87 have no `transition_args` at all**, so their real target slot had to be inferred from domain-name/sibling-verb context rather than read directly off the verb's own declaration. That inference is itself evidence for authoring the missing `transition_args` block on all 87 (or at least these 10) as part of R3's encoding step — not just correcting `requires_states` values in isolation.
